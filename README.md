# manga-Buy

中古漫画を「全巻が実際にそろう」「状態が読書に支障ない」「送料・必須費用込みで安い」の順に比較する、無料運用を前提とした漫画購入インテリジェンスです。

PC用リポジトリの設計思想を参考にしていますが、漫画用に独立した設定・データ・監視・検証を持ちます。

## 目的

- 第一候補9作品・第二候補16作品を追跡する。東京喰種は本編と :re を合わせた30巻構成として扱います。
- Amazon、メルカリ、楽天市場、Yahoo!ショッピング、Yahoo!オークション、BOOKOFFなどの検索リンクを作品ごとにまとめます。
- 出品URLを登録すると、許可された商品ページから構造化データ（JSON-LDなど）を取得し、価格・通貨・在庫状態を確認します。
- 全巻数、版、収録巻、商品の状態、送料、必須手数料が確認できた候補だけを「確認済み最安値」にします。
- 取得失敗・価格不明・在庫不明・送料不明を安い価格として扱いません。失敗時も元の商品URLをレポートに残します。
- 価格履歴と前回比を残し、誤検出・取得失敗・古い観測を監査できるようにします。
- GitHub ActionsとPython標準ライブラリを使用し、有料APIや有料サービスを必須にしません。

## 大原則：見かけの最安値で誤誘導しない

商品ページの価格だけでは購入総額は確定しません。確認済み総額は次の条件をすべて満たした場合のみ算出します。

1. 商品の価格が日本円で取得できた。
2. 対象作品・版・巻の範囲が確認できた。
3. 全巻数メタデータが確認済みで、必要な巻がすべて含まれている。
4. 在庫が商品ページの構造化データで「在庫あり」と確認できた。
5. 送料と必須手数料が既知で、7日以内に確認されている。
6. 価格と在庫の取得が24時間以内である。
7. 出品URL・作品一致・版一致・状態が確認済みである。

計算式は「商品価格 + 送料 + 購入必須手数料」です。不明な送料・手数料を0円として扱いません。クーポン・ポイント・キャンペーン値引きは、適用条件と最終決済額が証拠で確認できるまでは確定割引に含めません。

## 中古状態の基準

初期基準は「最安値を優先するが、読書に支障のある状態は除外」です。

- 原則許容：日焼け、軽い黄ばみ、表紙の擦れ、軽い折れ、帯なし、軽度の使用感。
- 価格・状態を明示して比較可能：レンタル落ち、管理シール、カバー欠品。通常品と同じ扱いにせず、明示して表示します。
- 除外：水濡れ・カビ、ページ欠損、読めない破損、重大な破れ、強い臭い、重い書き込みなど。
- 写真や説明から状態を確定できない場合は「状態未確認」とし、確認済みの最安ランキングから外します。

状態を点数だけで推測しません。状態情報がない候補を「良品」と扱いません。

## 作品の巻数と版

進行中作品は新刊発売で必要巻数が変わります。設定には確認済み巻数・暫定巻数・巻数確認ステータスを分けて持ちます。暫定巻数は検索用の参考であり、確認済み全巻判定には使用しません。

特装版、文庫版、完全版、ワイド版、電子書籍、裁断済み、レンタル落ちなどは巻数や価値が異なることがあります。異なる版を自動で混ぜません。版が不明なら要確認です。

## フォルダー

- config/manga_catalog.json：監視する25作品、候補グループ、版、巻数メタデータ
- config/marketplaces.json：検索リンク、許可ドメイン、価格取得ポリシー
- config/condition_policy.json：状態の許容・除外基準
- data/listings.json：人が確認して監視に登録した商品ページ
- data/discovered_candidates.json：検索から見つかった未検証候補
- data/observations.json：最新の価格・在庫取得結果
- data/price_history.jsonl：観測履歴。差分と失敗も監査可能
- data/reports/latest.md：最新レポート
- scripts/discover.py：公開検索結果から商品候補URLを発見
- scripts/monitor.py：登録済み商品URLの構造化データを取得
- scripts/manga_core.py：価格・状態・巻数・鮮度の判定
- scripts/report.py：最安候補、要確認、エラー、全商品リンクを出力
- scripts/validate.py：設定の整合性を検証
- tests：価格抽出と購入判定の回帰テスト
- .github/workflows/manga-price-monitor.yml：無料の日次自動処理

## 初期候補URLと確認状態

`config/manual_candidate_seeds.json` には、実際の商品ページURLを初期監視候補として登録できます。ここには候補タイトルとURLだけを保存し、検索結果に表示された価格は保存しません。価格・在庫は監視プログラムが商品ページから取り直し、版・全巻範囲・中古状態・送料/必須手数料を確認するまで、確認済み最安ランキングには入りません。

初期候補は売り切れを意味しません。URLを取得できない場合も在庫なしとは扱わず、エラーと元リンクをレポートに残します。部分セットは全巻セットとみなさず、巻範囲が確認されるまでは購入プランの確定に使いません。

## 使い方

### 1. 検索・監視を実行

GitHubのActionsタブで「Manga Price Intelligence」を開き、Run workflowを押します。通常は日次実行です。

ローカルで実行する場合、Python 3.11以降を使用します。

    python scripts/validate.py
    python -m unittest discover -s tests -v
    python scripts/discover.py
    python scripts/monitor.py
    python scripts/report.py

ネット検索・商品ページ取得はサイトの制限、構造変更、レート制限などで失敗する場合があります。失敗は在庫切れと同義ではありません。今回の公開検索で候補URLを得られなかった場合は `EMPTY`、初期候補だけを保持している場合は `SEEDS_ONLY` と表示し、検索が新しい候補を発見したと誤認させません。

### 2. 商品ページを監視対象に追加

data/listings.json に商品ページを追加します。商品URLを推測して作らず、検索結果から実際の商品ページを開いて確認してください。最低限、次を登録します。

- id：リポジトリ内で重複しない英数字のID
- manga_id：config/manga_catalog.json の作品ID
- listing_url：実在する商品のHTTPS URL
- included_ranges：作品の巻数マップ上で収録している巻の範囲
- title_match：作品一致が確認できた場合のみ EXACT
- edition_match：版一致が確認できた場合のみ EXACT
- condition：GOOD / ACCEPTABLE / RENTAL_USED / POOR / UNKNOWN
- damage_flags：確認できた状態問題
- shipping_jpy：送料が既知の場合は円整数。不明は null
- mandatory_fees_jpy：購入必須手数料が既知の場合は円整数。不明は null
- costs_checked_at：送料・必須手数料を確認した日時（JST ISO 8601）

例のスキーマは data/listings.json 内の説明に従ってください。商品価格は手入力せず、monitor.py が取得した観測に保持します。取得できないサイトの価格は「未取得」として扱い、画面に見えた価格を登録して自動観測のように見せないでください。

### 3. レポートの読み方

- 確認済み最安：全巻、版、在庫、状態、送料込み総額、観測鮮度がすべて確認済み。
- 暫定候補：価格・商品リンクは見つかったが、巻数メタデータや出品条件のいずれかが未確認。
- 比較不可：送料、必須手数料、在庫、状態、版、価格などが未確認。
- 取得エラー：元の商品リンクとエラー理由を表示。エラーを売り切れとは推定しない。
- 構造化データ取得成功・価格抽出成功・在庫あり確認済みは別指標です。価格が取得できても、在庫状態が不明なら確認済み最安には含みません。
- 検索リンク：その場で各サイトの現在の出品を確認するためのリンク。検索リンクの価格はこのリポジトリの観測値ではありません。

## 自動実行と制限

- デフォルトは1日1回。商品ページの大量アクセスは避けます。
- robots.txtでクロール禁止を検出した場合は取得を中止します。CAPTCHA、ログイン、アクセス制限を回避しません。
- 商品ページのJSON-LD等から価格や在庫が取れない場合、HTMLの文章から価格を推測しません。
- 発見されたURLは即座に購入候補の確定ランキングに入りません。巻数、版、状態、送料を確認して data/listings.json に登録する必要があります。
- レポートに「絶対最安」とは表示しません。登録・発見済みの候補内で確認できた最安値と表現します。
- 無料のGitHub Actionsは実行時間・頻度の上限、サイト側制限の影響を受けます。

## 現在の完成度

土台は fail-closed（証拠不足なら確定判定しない）です。初期データに販売中商品を捏造して入れることはしません。初回の自動実行後も実商品の登録・巻数メタデータ確認・各サイトの取得互換性検証が必要です。
